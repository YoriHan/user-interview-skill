# 用户访谈纲要整理 · Claude Code Skill

把腾讯会议转写（或粘贴的逐字稿）整理成「以找场景为核心」的结构化访谈纲要，并按编号上传到 GitHub。

## 何时用

- 刚做完一场用户访谈，手上有腾讯会议转写链接或逐字稿，想要一份能直接丢给研发/产品看的结构化纪要。
- 触发词：`/user-interview`、「整理用户访谈」、「访谈纲要」。

## 准备（一次性）

1. 安装 skill：把 `SKILL.md` 放到 `~/.claude/skills/user-interview/SKILL.md`。
2. 装好 headless browser 工具（抓取腾讯会议转写页要用）。
3. 跑 `gh auth login` 完成 GitHub 授权（上传纲要要用）。

## 用法

1. 在 Claude Code 输入 `/user-interview`。
2. 提供两样东西：① 腾讯会议转写链接，或直接粘逐字稿；② 受访者标识（用于文件名）。
3. 等它产出纲要 → 自动取下一个编号 → 上传到目标仓库。

## 输出：每份访谈一个编号 md（如 `03-Helio用户访谈-张三.md`）

按下面的顺序写每一节，每节都用原话支撑；跟该用户无关的节直接删掉，不留占位。

1. **用户背景** — 写清身份、团队规模、核心工作场景、AI 工具使用习惯与活跃度。
2. **AI 工具全景** — 列出所有在用工具：各自用在什么场景、付费金额、用户原话评价。
3. **核心使用场景（P0）** — 每个场景一个小节，逐项写：怎么配置 / 什么时候触发 / 产出什么 / 与竞品对比 / 配一句原话。
4. **Aha Moment 与卡点** — 各给一个最爽、最不爽的具体瞬间并配原话；未使用的功能写清「为什么没用」的真实前置原因。
5. **产品定位认知** — 用户怎么理解本产品 vs 其他工具（替代还是互补），引原话。
6. **问题反馈与需求** — 分三类：Bug（带复现/影响）/ 认知卡点（误解了什么、卡在哪）/ 功能需求（带场景）。
7. **付费意愿** — 写具体价格区间 + 货币单位 + 付费前提；信息缺失就标「访谈未覆盖」。

## 硬性规则（照做，别省）

- [ ] 关键结论必须有逐字稿原话，用 `> 「…」` 引。
- [ ] 原话 > AI 纪要：AI 纪要只当骨架，细节回原话核。
- [ ] 竞品点名道姓，评价写具体，别模糊化。
- [ ] 未使用功能写真实原因，别写「未探索」。
- [ ] 付费意愿要有数字，没有就明确标注缺失。
- [ ] 删掉与该用户无关的模块，不留空节占位。
- [ ] 不编造内容；不用破折号（——），用逗号或句号代替。
